# Architectural Decisions — append-only

## [2026-07-05] Props book quotes accessor — chose separate `prop_quotes()` on KalshiOrderBook over extending `as_kalshi_markets()` because `as_kalshi_markets()` returns ML-matcher-shaped dicts (title/ask/taker_fee/raw) and the Layer-2 contract requires the moneyline path byte-identical; props need a different shape (yes_ask/no_ask/qty_at_best).

## [2026-07-05] Kalshi qty in arb events — chose plumbing real `qty_at_best` from the book through `match_props` into `prop_arb` events now, over a null placeholder, because the contract's failure conditions require qty passed to `match_props`, match dicts flow into events via `**arb` (so the field lands in events either way), and the design doc says only the Poly size is null (LITE has no sizes). Layer 3 keeps the analysis/validation work.

## [2026-07-05] Ticker-channel prop handling — chose removing `KalshiPriceCache.update_from_ws()` and making the WS `ticker` branch a silent drop, over keeping a no-op method, because nothing subscribes props to the ticker channel after Layer 2 and dead write paths invite silent drift (rule 15's spirit). Obsolete ticker-update tests are replaced by ignore-assertions.

## [2026-07-05] Seq tracking on ack frames — per LEARNED_RULES rule 19, chunked subscribes share one sid and both `subscribed`/`ok` acks consume seq numbers; Layer 2 adds `note_seq()` so every sid+seq-bearing frame participates in gap detection, else ~19 prop subscribe chunks phantom-gap the connection.

## [2026-07-05] Mid-session prop discovery — chose a 60s time-guarded resubscribe diff in the WS message loop over waiting for reconnect/rollover, because book-or-nothing pricing otherwise blinds the scanner to intra-day listings the old ticker-channel path served via 60s REST prices (design says REST reconcile stays for "discovery" — discovery without subscription is broken).

## [2026-07-05] Props sweep trigger — chose gating `_run_props_arb_check_from_ws` on top-of-book signature changes over a time coalescer, because it restores the old ticker-channel trigger semantics (fire on price change, not deep-book churn) and keeps ~241 msg/s of book traffic from burning the shared event loop during the 24h validation.

## [2026-07-05] Sweep coalescer — top-of-book gating alone couldn't survive connect: every first snapshot legitimately changes a signature, so 2,793 subscriptions fired 2,793 back-to-back sweeps and the event loop missed keepalive pongs (observed live, close 1011). Added a 100ms leading+trailing coalescer on the hot trigger paths (Kalshi book frames, Poly WS frames); 100ms added latency is noise next to the REST-confirm RTT already on every new open.

## [2026-07-05] Correction to the "Props sweep trigger" entry above — its "24h validation" reference was boilerplate misapplied from the design doc's Layer-1 success criterion (ghost-filter false-positive rate over 24h live), not something that occurred for this change; the whole Layer 2 branch spans ~67 minutes of wall-clock commits. More importantly, that entry's claim that signature-gating alone "keeps ~241 msg/s of book traffic from burning the shared event loop" is incomplete: gating suppresses steady-state deep-book churn but cannot suppress the connect-time burst (every first snapshot legitimately moves the signature from `None`), which is exactly what caused the live disconnect the next entry (Sweep coalescer) fixes. Read the two entries together — gating + coalescer are both required, not gating alone.

## [2026-07-05] Taker fee model — replaced the flat 1%-of-ask `KALSHI_TAKER_FEE_RATE`/`POLYMARKET_TAKER_FEE_RATE` constants with each venue's actual parabolic formula (`fees.py`: `fee = theta * price * (1 - price)`, theta=0.07 Kalshi / 0.06 Polymarket US, per kalshi.com/fee-schedule and docs.polymarket.us/fees.md) over keeping the flat approximation, because the flat model understated fees ~2-3x near 50/50 pricing (letting false "arbs" through) and overstated them near the price extremes where props typically sit post-ghost-filter (masking real thin edges). Chose the continuous per-dollar fraction over replicating Kalshi's per-contract cent-rounding because the scanner works in price fractions, not discrete contract counts.

## [2026-07-05] Ghost filter F3 test fixtures after the fee fix — the corrected parabolic fees make it structurally near-impossible for a quote pair that cleanly passes F1/F2/F4 to also exceed the 10c `GHOST_MAX_GAP_CENTS` cap (max achievable is ~9.9c at the F1/F2 boundary, verified by grid search); real fees now absorb most of what used to look like a too-good-to-be-true double-digit-cent edge. Chose mocking `_ghost_filter_reason` to isolate F3 in `test_too_good_edge_is_edge_cap` over deleting the test or loosening ghost-filter constants, since the latter are a design decision outside this task's scope — worth revisiting `GHOST_MAX_GAP_CENTS` separately now that fees are correct.

## [2026-07-05] float-dust fix — chose round-to-cent-grid over integer-hundredths storage because quantities are 2-decimal dollar strings end-to-end and integer storage would ripple through prop_quotes()/event fields; also branched claude/fix-book-dust-levels off claude/feat-props-book-channel (not main) because the fix and tests touch the book-channel code and helpers PR #17 already modifies.

## [2026-07-05] ML ghost filter test fixtures — chose adjusting two plan fixture values (clean-pair poly_ask 0.68→0.70, mid-disagreement poly_ask 0.205→0.21) over copying the plan verbatim, because the plan's values imply a crossed synthetic Poly book (ask < 1 − opp_ask) that fires F4 "spread" before the behavior under test; adjusted values preserve each test's stated intent (F2 incident replay still 0.155 > 0.15).

## [2026-07-05] ML filter missing Poly opp ask — chose returning "one_sided" when a two-way match lacks the Poly opposite-side ask over the plan's silent pass-through, because the plan's stated goal is props parity and _ghost_filter_reason treats any missing two-sided quote as one_sided; a match whose Poly leg cannot be spread/mid-checked is unvetted, and the Task-5 REST confirm only re-checks the Kalshi leg. Three-way (soccer) exemption unchanged.

## [2026-07-05] ML edge-cap test fixture — chose a three-way (KXEPL) fixture over the plan's two-way MLB one, because for two-way pairs F2 mid-agreement makes gap > GHOST_MAX_GAP_CENTS unreachable (mid_k ≤ k_ask, mid_p ≤ p_ask, |mid_k − (1−mid_p)| ≤ 0.15 ⟹ k_ask + p_ask ≥ 0.85 ⟹ gap ≲ 8¢ < 10¢) and the plan's fixture is a crossed Poly book (ask 0.50 < derived bid 0.69) that returns "spread" first; soccer skips F2/Poly-F4 by design, so F3 is genuinely reachable there.

## [2026-07-05] ML REST-confirm test fixture — chose poly_ask 0.62 over the plan's 0.645, because at k=0.29/p=0.645 the parabolic fees give total 0.96315 >= ARB_THRESHOLD 0.96, so the plan's "live quote confirms and opens" test would be rejected with threshold_not_met_after_rest; at 0.62 total is 0.93855 (gap 2.15 cents), preserving the test's intent, and the stale-quote case (REST 0.36 -> total 1.0103) still rejects.

## [2026-07-05] ML confirm no-loop path — chose asyncio.get_running_loop()/else over the plan's try/except around create_task, because the plan's form constructs the coroutine object before create_task raises RuntimeError, leaking an unawaited coroutine (RuntimeWarning on stderr) on every cold-start tick that sees a new arb; semantics unchanged (skip, cooldown-expiry retry next check).

## [2026-07-05] ML ghost gate — chose a lookup-based gate inside check_arb_moneyline over threading two-sided fields through the four matchers, because the matcher output already carries the keys (ticker/slug/team) needed to join against as_kalshi_markets + poly cache, keeping the diff in one file. Soccer Poly legs get F1 only (draw mass invalidates yes_bid = 1 - opp_ask); F2 compares mid_k vs 1 - mid_p because ML legs are opposite teams.
